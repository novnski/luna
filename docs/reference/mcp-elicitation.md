# MCP forms and URL prompts

Codex's `mcpServer/elicitation/request` primitive form and URL modes, Claude Code's `elicitation` control requests and OpenCode 2's MCP elicitation and typed forms use the existing blocking question panel. A form asks for its fields, then requires an explicit Accept, Decline or Cancel response. The footer can decline or cancel from any page. Picking an MCP option does not submit or advance automatically. Optional fields can be skipped; valid schema defaults are shown. Validation errors retain the form and the engine refuses invalid responses without consuming its resolver.

Supported fields are strings, finite numbers, integers, booleans, string enums (`enum`, legacy `enumNames`, or titled `oneOf`) and multiselect enums (`items.enum` or titled `items.anyOf`). String lengths, numeric bounds, item counts, defaults, required fields and the `email`, `uri`, `date`, and `date-time` formats are validated. Titles map back to the exact wire enum values. Email validation checks basic address/domain syntax; it does not verify an address exists. Optional blank fields are omitted unless a default exists; a required unconstrained string can explicitly advance with empty text. Nested objects, unknown constraints/modes, malformed schemas, and obvious credential/payment-secret fields are declined. OpenAI-specific form/verification modes remain unsupported. The existing computer-use server retains its separate allow-once approval path; it cannot gain permanent/session allowance through a generic form.

Requests require a concrete server name, an opaque provider request ID and the native binding that owns them. The adapter owns that binding, passes immutable questions to the engine's run-owned pending map, and cancels their receiver when the native turn ends. The binding differs per provider:

- **Codex:** the active native thread and turn (`mcpServer/elicitation/request`; a null `turnId` binds to the thread's live turn).
- **Claude Code:** the CLI session and the `elicitation` control request ID.
- **OpenCode 2:** the form ID (`frm_…`) and the OpenCode session that owns the form. OpenCode's MCP elicitation forms (`form.created`, `metadata.kind: "mcp-elicitation"`) and its other typed forms (numbers, booleans, string formats and lengths, multiselect item counts) use this contract; plain question and choice forms (the native question tool, the websearch provider picker) use the ordinary question panel. The unattributed `"global"` owner is bound to the run's own session and shown on its chat only while its turn is active (each run owns a private server for one location); otherwise the form is cancelled with a message. Accept replies `POST /api/session/{owner}/form/{id}/reply {answer}`; Decline and Cancel send `DELETE /api/session/{owner}/form/{id}` (Decline with a message). A URL prompt is a single `external` field, answered `true` on Accept. Hidden fields take their defaults, conditional (`when`) fields are offered as optional and dropped when inactive, and anything outside this contract (pattern constraints, custom multiselect entries in a typed form, a website step mixed with fields, obvious secret fields, more than 16 fields) is cancelled at once with a message so OpenCode continues. A `409` or `404` reply means the form was settled elsewhere; `form.replied`/`form.cancelled` close the LUNA prompt.

When a provider settles a request elsewhere, the adapter drops the receiver and the engine retires the visible prompt; this also applies to plain provider questions, not only MCP forms and approvals. Client responses carry only the engine request ID and answers; client-supplied schemas or routing metadata never authorize a response. Retransmitted native IDs share the original pending callback. Different IDs can be pending concurrently. Resolving one preserves the other prompt and its awaiting-input status.

Limits are 64 KiB of incoming request JSON, 16 fields, 64 enum choices per field, 4 KiB of text/URL input, 16 KiB of submitted content, 32 generic requests per native turn, and a two-minute lifetime. Expiry or a closed provider channel resolves the visible pending part. Stop closes pending inputs. A recovered unresolved prompt can only be closed locally with decline/cancel; accepting it never becomes a resumed model turn.

A URL prompt displays its HTTP(S) origin and an **Open website** action. Opening is separate from responding. The full URL, including any authorization query/fragment, is only held in the adapter and engine's live resolver: it is serde-skipped, removed before emitting `InputRequested`, and excluded from `Debug`. A copy of that exact URL in the server's message is replaced with the origin. Embedded URL credentials and non-HTTP(S) schemes are rejected. Server messages remain untrusted display text, never executed instructions.

`McpElicitationUrl` accepts `chatId`, `requestId` and the existing optional `targetDeviceId`. It returns the URL for that exact live run/request only, checks cancellation, receiver liveness and expiry, and does not accept or consume it. Unknown/stale IDs return generic errors without the URL. Repeated fetches are harmless; the UI prevents concurrent duplicate fetches. The existing remote authorization policy keeps this credential-bearing endpoint owner-only: unauthenticated and authenticated remote read scopes are denied. Synced viewers may see the destination and submit ordinary forms through their existing command authority, but cannot retrieve the raw URL with read grants. A restart intentionally loses the URL.
