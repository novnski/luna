# L17 integration correction

This follow-up extends `8ce6c3f2` in the same isolated `codex/l17-backup-restore` worktree. Parent review/integration remains required.

## Implemented

- A `CredentialBroker` scope named `luna-backup` holds a caller-supplied 256-bit archive key. The local RPC accepts exactly 64 hexadecimal characters, stores only the decoded bytes in the scoped LUNA vault, zeroizes intermediate buffers, and returns no key. Key rotation and backup-root changes are refused after a recorded backup without an explicit migration plan, because older archives would become unreadable or misattributed. Tests use `CredentialBroker::in_memory_for_tests` exclusively; no real Keychain/provider store is probed.
- `BackupControl` persists source/destination configuration and verified receipt history in the isolated engine root. The source must be a separate marked copy-isolated root; the archive directory must have its own marker. Overlapping roots are rejected. Manual backup and export reopen/verify ciphertext before recording a receipt. A local engine timer checks once per hour and creates at most one backup per day after source modification, when automatic mode and the key are explicitly configured. Seven-daily/four-older-weekly retention candidates are reported; archives are not deleted.
- Local RPC methods expose redacted status, explicit configuration/key ingress, manual backup, export, full archive inspection, and verified staging. The relay service receives an `EngineRpc` without backup control, and backup methods are not forwardable. A normal unmarked LUNA root reports backup unavailable and performs no key or data access.
- Settings → Backups uses the existing Zeron page/card/action/theme components. It shows isolation status, source/destination, last freshly verified archive, manual backup/export/inspection/staging actions when ready, excluded categories, and explicit recovery limits. No native app was launched or visually QA'd in this workstream.
- Staging now checks available filesystem space before creating a directory (twice archive bytes plus 64 MiB headroom on Unix), and synthetic activation supports injected post-activation readback with automatic rollback on failure. The product RPC has no activation method. Verified stages remain for review; a second stage is refused while one exists.

## Exact remaining gates

- **Live LUNA backups remain unavailable.** The core takes the engine instance lock and snapshots an offline/copy-isolated source. A write barrier or online cross-store snapshot protocol is required for a running profile; no live profile or data was read or mutated here.
- The hourly due check uses allowlisted file modification times as a change signal for isolated copies. It can create an extra backup after SQLite sidecar/index activity; it is not a transaction-sequence proof of a meaningful live user change.
- **Recovery-key ownership is incomplete.** A trusted local caller can import owner-held key material, but this branch does not generate, display, print, or export a recovery code, and the native page has no secret-entry control. A user must already hold the key independently. Normal app roots cannot enable the service by default.
- **Live restore remains blocked.** Staged SQLite activity/search rows need an authoritative rebuild before activation; provider-native stores, credentials, grants, workspaces, absolute external paths, and schedules are never implicitly restored. The synthetic readback callback is not an actual engine restart/Doctor validation. There is no live activation RPC.
- Free-space checking is a conservative preflight, not a reservation; concurrent disk consumption remains possible. Windows staging stays unsupported until an equivalent free-space probe exists. Interrupted plaintext SQLite snapshot temp directories and verified staging directories require an owner-reviewed cleanup flow in L18. Retention selection does not purge archives.
- The repository has no single exposed protocol-version constant to put in the manifest. Native visual QA and parent source review are still required. **Do not mark L17 accepted or complete from this branch alone.**
