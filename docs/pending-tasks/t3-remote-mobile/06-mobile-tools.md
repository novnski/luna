# T3 Code mobile remote developer tools — source audit

Snapshot: `pingdotgg/t3code` at `a8bdfdb54181fb5c9d43f2747112c137a804d016`, inspected on 2026-10-11. This is **static source and checked-in documentation evidence**, not a live mobile-device verification. “Mobile” below means the native React Native app in `apps/mobile`, not a shared server API merely callable by a different client. The server/environment and its Git credentials, files, PTYs, browser, and simulator remain on the host; the phone is a remote client. [Project instructions](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/AGENTS.md#L1-L47) and [remote access guide](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/user/remote-access.md#L1-L4).

## Capability matrix

| Area | Reachable on native mobile | Confirmed limitation / dependency |
|---|---|---|
| Host terminal | Open/attach several thread PTYs, read existing output, type/paste/special keys, resize, clear, capture output into chat context, run saved project scripts | `terminal:read` can only observe existing sessions; `terminal:operate` is needed to create/write/resize/clear/close. Host shell/PTY must be available; native Ghostty view can fall back to text UI. |
| Workspace files | Search and expand tree, read source with highlighting and line navigation, preview Markdown/HTML/PDF/images/audio/video, copy path/content, save/share media | No mobile workspace text editor or write-file command is wired in the inspected file route. Text preview is capped at first 1 MiB; absolute host file links are read-only. |
| Change review | Native diff for branch comparison, uncommitted tree, and per-turn checkpoints; changed-file navigator, line selection, comment drafted into agent message | This is **local Git/worktree review**, not a pull-request Code tab. Native renderer may fall back to raw patch; binary/large content can be suppressed. |
| Git | Status, pull, selected-file commit with custom/auto message, push, PR creation, default-branch warning, branch create/switch, worktree creation, linked PR status/open host URL, merge-back where applicable | No separate mobile stage/unstage control found. Mobile has no in-app PR diff/Code tab, PR line-comment or merge/reviewer surface. Branch/worktree changes need both source-control write and orchestration operate scopes. |
| Host browser preview | View a thread's server browser tabs, take/release control, navigate/back/forward/reload, interact with page, respond to dialogs, mobile file picker/upload and download/share, appearance/zoom/viewport/cookie/cache options | Browser runs on host, so `localhost` means host. Mobile only opens existing thread tabs in the inspected routes; tab creation is agent/server-side. Audio is not forwarded. iOS PiP only; Linux host may need Chromium setup. |
| iOS/Android simulator | Watch and interact with a thread's open device session, select multiple devices, Home/Back/app switcher/rotate, stream reload, shut down | Mobile route lists **existing thread sessions**; it does not expose the desktop device setup/boot/tools drawer. Simulator runs on environment/device host with platform SDK dependencies. Secure origin needed for full video. |
| Host desktop/computer control | No native mobile remote-desktop surface found in this lane | T3’s `device` feature is simulator/emulator control; server browser is its own headless browser. Do not label either as general host-screen remote desktop. |

## Terminal: actual mobile → shared runtime → server path

The thread header opens `ThreadTerminal`, including on Android (whose header actions are separately rendered); terminal route controls create/switch sessions and expose text-size adjustment. [Android/header entry](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/threads/ThreadHeader.tsx#L25-L54), [route selection/new session menu](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/terminal/ThreadTerminalRouteScreen.tsx#L96-L176), [thread terminal launch](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/threads/ThreadRouteScreen.tsx#L600-L652). The route checks session scopes, chooses a writable attach or a read-only observe, and replays the measured grid after an attach or reconnect. [Mobile scope/attach](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/terminal/ThreadTerminalRouteScreen.tsx#L279-L295), [observe vs attach](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/terminal/ThreadTerminalRouteScreen.tsx#L457-L489), [grid replay](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/terminal/useTerminalGridSync.ts#L13-L51), [runtime switch](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/state/use-terminal-session.ts#L28-L60).

Mobile input goes through `terminalEnvironment.write`; resize/clear/open go through the same shared RPC atoms. The route has paste and modified-key handling, toolbar actions, a capture button, reconnect/error handling, and closes a session on exit. [Write/resize/paste](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/terminal/ThreadTerminalRouteScreen.tsx#L793-L913), [open/close/clear lifecycle](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/terminal/ThreadTerminalRouteScreen.tsx#L978-L1087), [surface/capture](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/terminal/ThreadTerminalRouteScreen.tsx#L1276-L1305), [shared RPC atoms](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/state/terminal.ts#L39-L102), [server handlers](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/ws.ts#L2861-L2887). The native view uses Ghostty on iOS and `libghostty-vt` plus Canvas on Android; the fallback still shows buffered text and a simple input. [Native module](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/modules/t3-terminal/README.md#L1-L23), [view/fallback](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/terminal/NativeTerminalSurface.tsx#L69-L85), [native bridge](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/terminal/NativeTerminalSurface.tsx#L187-L257).

The server emits an initial snapshot and then live PTY events, buffering events during snapshot creation so no gap is lost. History is bounded to 5,000 lines and 8 MiB on the environment, including reconnect/restore; the mobile renderer may display less. [Server snapshot/live handoff](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/terminal/Manager.ts#L2812-L2874), [history guide](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/user/terminal.md#L1-L8). Authorization distinguishes `terminal:read` and `terminal:operate` on the server too. [RPC authorization](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/RpcAuthorization.ts#L178-L187).

## Files: read and preview, no workspace editing UI

The mobile tree issues `projects.listEntries` per expanded directory and debounced `projects.searchEntries` (up to 200 results), with refresh and per-directory error handling. [Mobile query](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/files/useFileTreeEntries.ts#L11-L32), [expansion](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/files/FileTreeBrowser.tsx#L142-L195), [server list handler](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/ws.ts#L2635-L2655). `filesystem:read` is checked before listing and reading, and the file route calls `projectEnvironment.readFile`. [Mobile access gate](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/files/ThreadFilesRouteScreen.tsx#L435-L449), [read query](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/files/ThreadFilesRouteScreen.tsx#L691-L714), [server scope](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/RpcAuthorization.ts#L148-L153).

The file screen has source and rendered modes, Markdown rendering, HTML/PDF/WebView previews, image/audio/video viewers, copy path/content, media save/share, and file-view refresh. Text read shows a partial-file notice at 1 MiB. [Preview modes/media](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/files/ThreadFilesRouteScreen.tsx#L234-L332), [1 MiB notice](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/files/ThreadFilesRouteScreen.tsx#L307-L312), [menu actions](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/files/ThreadFilesRouteScreen.tsx#L773-L856). The `SourceFileSurface` contract accepts contents/path/selection/refresh but no edited value/save callback; the route’s only workspace file RPC is read. A server `projects.writeFile` RPC exists, separately gated by `filesystem:write`, so server capability must not be mistaken for native mobile editor UI. [Source surface props](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/files/SourceFileSurface.tsx#L40-L52), [mobile source use](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/files/ThreadFilesRouteScreen.tsx#L307-L332), [server read/write handlers](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/ws.ts#L2646-L2667). Host absolute paths may be read as agent file links, but cannot be written back; the user guide calls these read-only. [Contract](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/contracts/src/project.ts#L435-L450), [guide](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/user/composer.md#L298-L306).

Separate from workspace editing, the composer uploads device files as agent message attachments, and the server browser can upload a phone-picked file into a web page. These are distinct flows. The browser upload uses a native document picker, multipart POST and `preview:operate`; downloads are offered through the phone share sheet. [Browser mobile handoff](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/browser/PreviewStreamWebView.tsx#L62-L109), [server upload authorization and limits](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/preview/ServerBrowserStream.ts#L236-L264), [composer attachment guide](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/user/composer.md#L32-L50).

## Review and Git: mobile local changes versus hosted PR review

Mobile Review offers branch-range “Changes,” working-tree “Uncommitted,” and per-turn checkpoint sections. It requests Git diff previews through the environment, plus checkpoint diffs for turns; the server has a diff-preview RPC under `filesystem:read`. [Section model](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/review/reviewModel.ts#L9-L24), [section query](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/review/useReviewSections.ts#L39-L97), [section menu](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/review/ReviewSheet.tsx#L118-L150), [server handler/scope](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/ws.ts#L2859-L2860). The native renderer gets file rows, syntax tokens, selection/collapse/viewed state and scroll navigation; a raw-patch fallback exists when native rendering cannot resolve. [Native renderer](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/review/ReviewSheet.tsx#L755-L813), [fallback rationale](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/review/ReviewSheet.tsx#L666-L678). A selected line comment is appended to the **thread composer draft** with context/optional images; it does not post a hosted PR review comment. [Comment submit](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/review/ReviewCommentComposerSheet.tsx#L139-L152).

[Git status/actions](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/threads/git/GitOverviewSheet.tsx#L96-L136), [rows](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/threads/git/GitOverviewSheet.tsx#L289-L350), [linked PRs](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/threads/git/GitOverviewSheet.tsx#L353-L399). ## Browser preview: streamed host Chromium, controlled by one owner

Mobile only offers the preview button when the selected thread has server browser tabs and the host advertises `serverBrowser`; its route lists/switches existing tabs. [Thread gate](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/threads/ThreadDetailScreen.tsx#L345-L359), [button gate](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/threads/ThreadDetailScreen.tsx#L1239-L1252), [mobile tab route](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/browser/BrowserPreviewRouteScreen.tsx#L80-L103). The mobile WebView embeds a thin stream client, not the site itself; it obtains connection/ticket access, opens `/api/preview-stream/ws`, paints frames and forwards input. The server authenticates `orchestration:read` to watch and `preview:operate` to drive. [Mobile access](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/state/preview.ts#L148-L165), [shared WebSocket client](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/preview/serverBrowserStream.ts#L226-L250), [server authorization](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/preview/ServerBrowserStream.ts#L53-L92).

The ownership protocol distinguishes agent/you/another viewer/read-only; mobile can take/release when allowed, and shared client rejects input without control. Back/forward/address/reload are gated on streaming and owner control. The tab menu’s appearance, zoom, viewport presets, hard reload and site-data clear operate via environment RPC and do not require the viewer ownership token. [Control states/input gate](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/preview/serverBrowserStream.ts#L18-L41), [client command guard](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/preview/serverBrowserStream.ts#L391-L399), [mobile control button](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/browser/PreviewStreamWebView.tsx#L323-L345), [address controls](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/browser/BrowserPreviewRouteScreen.tsx#L207-L270), [tab menu](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/browser/BrowserTabMenu.tsx#L24-L44).

The browser is a **host-side headless Chromium** shared with agent tabs. `localhost` reaches the host, with no per-phone local port forward required. It can stay active with no client connected; first use may download about 120 MiB, and some Linux hosts need sandbox/libraries setup. Upload/download/clipboard are explicitly bridged to the phone; audio is not. [Remote browser guide](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/user/remote-access.md#L185-L220), [mobile picker/share implementation](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/browser/PreviewStreamWebView.tsx#L62-L109). iOS supports PiP after the app backgrounds; Android’s WebView does not in this route. [PiP platform gate](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/browser/BrowserPreviewRouteScreen.tsx#L113-L136). Frame flow bounds include max 64 unacknowledged frames and an 8 MiB socket buffer; slower viewers disconnect rather than let backlog grow. [Server stream bounds](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/preview/ServerBrowserStream.ts#L28-L35), [slow-viewer path](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/preview/ServerBrowserStream.ts#L145-L150).

## Device preview: simulator control, not host desktop sharing

The thread button appears only when `threadDevicePreviews` finds an existing session owned by this thread, and the mobile viewer selects among those sessions; it does not show the full desktop device picker/setup flow. [Thread button](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/threads/ThreadDetailScreen.tsx#L1239-L1251), [session filter](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/devices/threadDevicePreviews.ts#L3-L19), [viewer selection](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/devices/DevicePreviewRouteScreen.tsx#L94-L103). The phone can tap/type through the stream, use Home/Back/app switcher/rotate as applicable, reconnect, choose another open device, and request shutdown; stream closes when viewer leaves while device stays available unless powered off. [Mobile controls](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/devices/DevicePreviewRouteScreen.tsx#L205-L280), [native WebView command bridge](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/devices/DeviceStreamWebView.tsx#L115-L180), [product guide](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/user/devices.md#L61-L70).

The hub runs loopback on host and T3 proxies a limited allowlist through its same `/api` origin; read paths need `orchestration:read`, input socket and tuning need `orchestration:operate`. This is why LAN/Tailscale/Connect routes carry the stream without exposing the helper directly. [Proxy design/allowlist](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/device/DeviceHubProxy.ts#L1-L53), [proxy auth](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/device/DeviceHubProxy.ts#L150-L194), [mobile access ticket](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/state/device.ts#L14-L43). Simulators are host resources: iOS needs macOS/Xcode, Android needs SDK/emulator/virtual device; remote SSH device hosts are also possible. HTTPS/localhost is needed for live video; over plain HTTP remote origin iOS uses slower still images and Android cannot show video. ## Luna implications and proposed acceptance tests

These are *candidate requirements for Luna*, not verified Luna gaps; the Luna lane must mark each as existing/partial/missing after current code and app readback. Prioritize the common host-facing primitives over duplicating T3’s UI verbatim:

1. A per-environment, per-thread terminal service with bounded server history, snapshot-plus-live attach, multiple PTYs, scope-separated observe/operate, input and grid resize, and reconnect replay. E2E: start a long-running host command on desktop, attach from phone, enter text and Ctrl-C, resize/rotate, disconnect network, reconnect, confirm one PTY and ordered output without duplication; connect with read-only grant and confirm output visible but input/open/clear blocked. Preserve a transcript and server session IDs as repeatable artifacts.
2. A host workspace inspector with read scope, lazy directory tree/search, file source and media previews, signed asset URL renewal, and explicit write scope if Luna wants real phone editing. E2E: inspect a representative repo remotely, deep-link to a line, preview a large/truncated file and media, revoke read scope, and confirm both UI and server reject further access. For editing, save with conflict/version protection and confirm host bytes plus another client’s refresh; a chat attachment upload must not be confused with editing a workspace file. Save fixture tree and before/after hashes.
3. Three distinct review models: uncommitted tree, base-branch comparison, and per-turn diff. E2E: make staged/unstaged/untracked and committed changes, verify section membership and diff counts from Git, navigate large/binary diffs, add a line comment into the agent composer, and verify it has not posted to a hosted PR. Keep Git status/diff snapshots and mobile screen recording.
4. Mobile Git actions with host credentials, explicit scope checks, selected-file commit, branch/worktree operations, progress, default-branch confirmation, PR creation/status/open URL. E2E: on a disposable remote repo, commit only one of two changed files, push/create PR, verify exact host commit tree and remote PR; exercise read-only grant and occupied worktree branch. Keep commit SHA, status JSON and PR URL. Decide separately whether Luna should implement **hosted PR diff/review on mobile**—T3 currently does not.
5. A host browser stream for agent tabs with watch versus exclusive control, in-band ownership, phone clipboard/file picker/download bridge, host-local URL access, reconnect/ticket renewal and bounded backpressure. E2E: agent opens a local dev server URL, phone watches, takes control, types/uploads/downloads, releases control, disconnects/reconnects, and checks host page state; test one competing viewer and read-only grant. Keep a video and server tab/control event log.
6. If Luna needs remote simulator QA, proxy a narrow authenticated device stream and input surface from the environment rather than exposing an unauthenticated helper. E2E: agent opens a simulator, phone views/taps and sends Home, viewer exits without shutting it down, reconnects over LAN and tunnel, and read-only scope blocks input. Save video, host device/session IDs and stream diagnostics. General desktop/computer sharing is a separate product decision and cannot be inferred from T3’s simulator preview.
