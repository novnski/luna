# T3 Code remote authentication, pairing, and revocation

Source: extracted read-only `pingdotgg/t3code` tree supplied at commit `a8bdfdb54181fb5c9d43f2747112c137a804d016` (2026-10-11 research snapshot). Permalinks use `https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/<path>#Lx-Ly`. The extraction has no `.git` directory, so the commit ID was provided with the snapshot and was not independently checked with Git. This is source review, not a running-server or mobile-device test. Existing tests are cited as an independent intended-behavior cross-check; I did not execute them.

## Executive findings

1. The host T3 **environment** is the authorization authority regardless of direct LAN, Tailscale, or T3 Connect route. A pairing URL transfers a short-lived bootstrap secret; redemption creates a **different, persistent, scoped session**. The mobile client stores that session token in Expo SecureStore, reconnects using it, and does not need the original pairing code. See [environment auth](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/internals/environment-auth.md#L1-L29), [pairing implementation](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/connection/onboarding.ts#L111-L155), [mobile storage](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/connection/storage.ts#L105-L130), and [user guide](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/user/remote-access.md#L54-L63).
2. Ordinary pairing grants a broad **standard** operating set, but excludes `access:read`, `access:write`, and `relay:write`. Administrative startup pairing grants those three too. A currently authorized admin can delegate only scopes it holds, enforced on the server. [Scope definitions](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/contracts/src/auth.ts#L82-L125), [standard/admin lists](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/contracts/src/auth.ts#L205-L225), [issue handler](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/http.ts#L430-L447), [startup grant](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.ts#L1091-L1106).
3. Revoking an authorized client invalidates later **session-authenticated** HTTP/ticket use and its live WebSocket: the socket races its RPC lifetime against the session's revoke/expiry listener. Revoking an **unused pairing link** is different; it prevents future redemption but does not revoke a session already minted from it. An already-issued signed asset URL is another distinct bearer capability: it remains usable until its own expiry after the issuing session is revoked. [Session revoke](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/SessionStore.ts#L998-L1050), [invalidation listener](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/SessionStore.ts#L1053-L1079), [WS lifecycle](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/ws.ts#L3218-L3232), [pairing-link revoke](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/PairingGrantStore.ts#L382-L396), [asset exception](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/internals/environment-auth.md#L111-L120).

## Direct-pairing wire sequence

1. An admin uses `t3 pair` or desktop/web Connections to issue a link. The default server token is 12 characters from a 32-symbol ambiguity-free alphabet, generated with rejection sampling; its default lifetime is **5 minutes**. A development startup URL may last 24 hours; a normal startup URL has admin scopes and the ordinary lifetime. The server stores the grant with allowed scopes, subject, label, expiry, and optional proof-key thumbprint. [Generator and TTL](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/PairingGrantStore.ts#L254-L300), [issuance](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/PairingGrantStore.ts#L398-L452), [startup exception](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.ts#L1098-L1124). Caveat: SQL persists the **raw grant credential**, not a hash; see [insert](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/persistence/AuthPairingLinks.ts#L125-L156) and [lookup](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/persistence/AuthPairingLinks.ts#L236-L255). Its public access snapshot omits the credential ([contract](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/contracts/src/auth.ts#L325-L342)); this does not encrypt the local database.
2. Direct URLs place `token` in the URL fragment (`/pair#token=...`), so it is not sent by the browser as a request parameter. A hosted-app link puts the backend address in the query and the secret in its fragment. [URL construction](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.ts#L1155-L1165), [hosted construction](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/web/src/hostedPairing.ts#L73-L87), [architecture note](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/internals/remote.md#L47-L62). Older/alternative query-token input remains accepted by common/mobile parsing; thus *all* inbound links cannot be claimed fragment-only. [Common parser](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/shared/src/remote.ts#L144-L162), [mobile parser](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/connection/pairing.ts#L45-L70).
3. Mobile has a QR scanner and manual host/code entry. A `t3code://pair?pairingUrl=<encoded URL>` QR payload is unwrapped, and raw URLs are accepted. The scanner **prefills** fields and stops re-reading; the user then submits. Production route/deep-link prefill and automatic connection are disabled (`__DEV__` only), explicitly to avoid attacker-chosen host/token auto-pairing. [Parser](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/connection/pairing.ts#L73-L92), [scanner](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/connection/ConnectionsNewRouteScreen.tsx#L129-L145), [dev-only deep-link gate](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/connection/ConnectionsNewRouteScreen.tsx#L53-L60), [submit](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/connection/ConnectionsNewRouteScreen.tsx#L159-L195). [Parser tests](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/connection/pairing.test.ts#L10-L63) independently cover IP scheme, hostname scheme, QR deep link, and hosted link.
4. The shared client normalizes the backend origin and fetches the public environment descriptor before spending the one-time code. If adding a route to a known environment, a different environment ID is rejected first. Then client POSTs form-encoded OAuth token exchange to `/oauth/token` with `grant_type=urn:ietf:params:oauth:grant-type:token-exchange`, `subject_token=<code>`, custom bootstrap token type and access-token type, optional scopes and client presentation metadata. The server atomically consumes the grant and returns a **Bearer** token for direct mobile. [Onboarding](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/connection/onboarding.ts#L111-L155), [request](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/authorization/remote.ts#L115-L140), [wire schema](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/contracts/src/auth.ts#L227-L231), [request/response contracts](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/contracts/src/auth.ts#L298-L317), [server exchange](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.ts#L905-L965).
5. Atomic SQL `UPDATE ... WHERE revoked_at IS NULL AND consumed_at IS NULL AND expires_at > now ... RETURNING` makes only one redemption win, enforces any bound proof key, and rejects a request with **no overlapping granted scope** without spending the code. The issued session gets only the intersection of requested and delegated scopes. A valid but disjoint request leaves the link for a later valid attempt. [Consume SQL](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/persistence/AuthPairingLinks.ts#L160-L195), [grant handling](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/PairingGrantStore.ts#L559-L621), [intersection](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.ts#L913-L943); [racing-consumers test](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/PairingGrantStore.test.ts#L96-L123), [disjoint-scopes test](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.test.ts#L365-L405).
6. The token persists separately from endpoint profiles in the mobile connection catalog; that entire catalog is serialized into `expo-secure-store` as key `t3code.connection-catalog.v1`. Re-pairing the same environment/origin replaces that route's credential. The catalog deliberately avoids putting credentials in the public route/profile entry, although they are grouped inside one secure-storage JSON document. [Catalog store](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/connection/catalog-store.ts#L13-L18), [read/write](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/connection/catalog-store.ts#L51-L58), [credential component](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/connection/storage.ts#L105-L130), [Expo storage adapter](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/persistence/mobile-secure-storage.ts#L31-L48), [registration](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/connection/registry.ts#L650-L712).
7. Steady-state bearer HTTP calls use `Authorization: Bearer <token>` to check `/api/auth/session` and mint a **five-minute WebSocket ticket** over authenticated HTTP; the short ticket, not the month-long bearer, appears in the `/ws?...` URL. Browser bootstrap goes through `/api/auth/browser-session` and receives an `HttpOnly`, `SameSite=Lax`, path `/` cookie. The normal bearer/cookie session lifetime is **30 days**; T3 Connect DPoP environment tokens last **one hour**. [Client HTTP](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/authorization/remote.ts#L142-L176), [ticket issuance](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.ts#L1167-L1206), [cookie](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/http.ts#L298-L340), [session TTLs](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/SessionStore.ts#L432-L433), [DPoP TTL](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.ts#L921-L930). Browser cookies are not marked `Secure` by these `Cookies.set` calls; HTTPS transport must be supplied by the route/proxy.

## Scope enforcement and administration

The server authenticates each HTTP request, and each WebSocket upgrade yields the session's scope list. WebSocket RPC middleware checks an explicit required scope before each handler; the map is tied to the RPC group so an unmapped new RPC is a type error. It covers read and operation paths and supports payload-sensitive requirements. The client also uses `permissions` (new exact grant) or legacy `scopes` for UI availability, but this is advisory only. [HTTP middleware](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/http.ts#L219-L259), [WS principal](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/ws.ts#L3153-L3178), [RPC scope map](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/RpcAuthorization.ts#L40-L59), [check](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/RpcAuthorization.ts#L275-L281), [client compatibility](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/contracts/src/auth.ts#L130-L201). One caveat for design review: `dispatchCommand` is mapped to `orchestration:operate`; the host remains the final enforcement point for sensitive command semantics.

`access:read` lists active, unspent link metadata and client sessions (subject, scopes/permissions, method, label/IP/user-agent/device type, issue/expiry, last connection, connected/current). `access:write` creates links and revokes them or clients. A client cannot revoke its own current session through `revokeClient`, though `revokeOtherClients` keeps current and removes all others. [Response model](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/contracts/src/auth.ts#L333-L371), [HTTP operations](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/http.ts#L455-L527), [self-revoke guard](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.ts#L1127-L1153). Client label/device type/OS is supplied during token exchange, with IP/User-Agent inferred from the request; it is **display metadata, not verified device identity**. [Metadata derivation](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/utils.ts#L182-L198), [exchange fields](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/http.ts#L383-L398).

The desktop/web Connections UI gates link issuance and access management with these permissions ([UI checks](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/web/src/components/settings/ConnectionsSettings.tsx#L2235-L2236), [delegation check](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/web/src/components/settings/ConnectionsSettings.tsx#L1044-L1068)). Mobile route UI offers saved-route edit/reconnect/remove and current route permissions, but source search of `apps/mobile/src` found no `AuthAccessReadScope`/`AuthAccessWriteScope` or `revokeClient` use; consequently a normally paired phone cannot manage other sessions, and even an admin-scoped phone does not appear to expose an access-management screen. This is an **absence from inspected mobile source**, not a device-verified behavior. [Mobile route actions](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/connection/ConnectionEnvironmentRow.tsx#L184-L210), [mobile permission guide](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/user/remote-access.md#L91-L102).

Mobile **Remove environment** is a local forget action, not host session revocation: its UI says “Remove from this device?”, the controller calls the local environment catalog removal, and that removal erases the local route/credential catalog and cache without invoking `/api/auth/clients` revocation. The server-side session can remain active until expiry or an admin revokes it. [Mobile confirmation](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/state/use-remote-environment-registry.ts#L156-L193), [controller](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/connection/useConnectionController.ts#L91-L94), [registry removal](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/connection/registry.ts#L819-L856), [catalog deletion](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/platform/storageDocument.ts#L173-L199). This distinction should be explicit in Luna's “forget phone” versus “revoke phone” UX.

Signed asset URLs further limit what “revoke immediately” means in T3. Minting `assetsCreateUrl` requires `filesystem:read` for host/workspace paths or `orchestration:read` for other supported assets, and produces a signed URL carrying an expiry (ordinary token TTL is one hour). The GET `/api/assets/*` route calls `resolveAsset` directly; the resolver checks signature, expiry and asset/file identity, with no issuing-session lookup. It can therefore still serve an issued URL after the session's HTTP credential and socket are invalid. Atomic file replacement breaks a `media-file-exact` URL through canonical path and device/inode rechecks, but ordinary session revocation does not. [Mint scope](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/RpcAuthorization.ts#L249-L264), [TTL and claims](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/assets/AssetAccess.ts#L67-L70), [mint](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/assets/AssetAccess.ts#L786-L811), [GET route](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/http.ts#L396-L418), [resolve checks](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/assets/AssetAccess.ts#L813-L829), [exact-media identity](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/assets/AssetAccess.ts#L911-L935), [opened-file identity](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/assets/MediaFile.ts#L48-L99), [design note](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/internals/environment-auth.md#L111-L120).

## Route trust, relay boundary, and failure cases

- Direct LAN, Tailscale HTTPS, and Connect tunnel are **routes to the same environment**, not separate server authority. The public descriptor/environment ID is checked before sending a saved credential to a direct route, reducing accidental disclosure after moving to a LAN with a reused address. An unresponsive route may still be attempted later, so do not describe the descriptor check as a cryptographic proof of route ownership. [Architecture](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/internals/remote.md#L1-L45), [route check](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/connection/driver.ts#L138-L180), [user route behavior](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/user/remote-access.md#L65-L101).
- The T3 Connect **cloud account and relay link are separate from environment login**. With an active cloud link, relay brokers a one-time environment grant bound to the client's DPoP public key; the client exchanges it with the environment for a proof-bound token. The relay does not receive that session token, and an invalid DPoP proof must fail rather than fall back to bearer. The relay nevertheless holds mint-request signing authority, so compromise there can authorize new grants. [Trust doc](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/docs/internals/t3-connect.md#L35-L63), [proof-bound exchange](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/authorization/remote.ts#L86-L113), [server proof check](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.ts#L729-L779), [proof-key grant check](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/PairingGrantStore.ts#L607-L612). The cloud relay device registration used for notifications/live activities is separate again: mobile creates a stable agent-awareness device ID and registers a push token with the relay after sign-in; that ID does not appear in the environment session's authorization schema. [Mobile ID](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/persistence/mobile-storage.ts#L191-L225), [relay registration flow](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/agent-awareness/remoteRegistration.ts#L74-L101), [auth metadata schema](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/contracts/src/auth.ts#L344-L365).
- The mobile DPoP private JWK is generated locally, validated against its public point when loaded, and saved separately in Expo SecureStore. The signer caches the loaded key for the app lifetime. This is additional proof material for Connect, distinct from the direct-pairing bearer in the connection catalog and from the push-registration device ID. [Key storage and validation](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/cloud/dpop.ts#L195-L236), [signer cache](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/cloud/managedRelayLayer.ts#L15-L53).
- The mobile URL builder defaults a scheme-less **IP literal to HTTP**, hostname to HTTPS; explicit schemes are preserved. Shared remote URL normalization accepts HTTP/HTTPS and WS/WSS. Hence local direct pairing may send the one-time code and later bearer over plaintext HTTP. Tailscale HTTPS and Connect provide HTTPS routes, but a QR fragment alone does not protect the code once POSTed to an HTTP backend. [Mobile URL builder](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/connection/pairing.ts#L6-L42), [builder tests](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/mobile/src/features/connection/pairing.test.ts#L10-L28), [shared accepted schemes](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/shared/src/remote.ts#L72-L129). This is a transport property, not an assertion that T3's cleartext mode is exploitable on a given trusted LAN.
- Failure modes include expired/used/revoked code, mistaken endpoint or incompatible protocol, missing/invalid stored bearer, expired/revoked session, and T3 Connect cloud sign-out/renewal failure. Backend code distinguishes these; client runtime maps them to connection-blocked/transient states. The user may need to mint a fresh link after an interrupted exchange that spent its code but failed before storing the issued token: consumption happens before session issue and client catalog registration. [Consume-before-issue](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/EnvironmentAuth.ts#L905-L943), [client register-after-exchange](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/packages/client-runtime/src/connection/onboarding.ts#L131-L163), [ticket/session rejection](https://github.com/pingdotgg/t3code/blob/a8bdfdb54181fb5c9d43f2747112c137a804d016/apps/server/src/auth/SessionStore.ts#L766-L856). This lost-response scenario is an inference from ordering, not an observed failure.

## Recommendations for Luna pending requirements (not claims about Luna's current state)

1. Define a host **environment identity** independent of IP, plus a public descriptor/protocol version. A phone should check expected identity before redeeming a one-time code, and a saved route should be rechecked before presenting a durable credential.
2. Build a one-time, expiring, scope-bearing pairing grant with an admin-controlled QR/code UI. Put the secret in a URL fragment; keep it out of the access read model and ordinary logs. Do not auto-redeem arbitrary production deep links. Provide explicit re-pair and consumed/expired feedback. Consider hashing stored grant secrets; T3 currently stores them raw.
3. Exchange the grant for a separate long-lived, revocable **device session** stored in platform secure storage. Keep access scope, server identity, and endpoint route separate in the data model. Preserve multiple routes to one host without conflating their authorities.
4. Enforce per-command permissions on the host as well as UI gating. Make initial mobile grants sufficient for intended operation but omit access management by default. Plan exact granularity (`read`, `operate`, filesystem, terminal, settings, provider management, device management) and old-client compatibility before exposing broad remote control.
5. Expose host-side authorized-session inventory and both unspent-link and session revocation. Model connected/current, expiry, last seen and display-only device metadata. On revocation, invalidate live sockets, outstanding tickets and subsequent session-authenticated HTTP requests. Specify separately whether previously minted file/media URLs survive until short expiry (T3 behavior) or are session-bound and stop at revocation (stricter Luna option); the latter needs an issuing-session or capability-revocation check at asset GET time and should be tested against media seeking.
6. Separate direct-network authentication from optional cloud relay/account login and from push-notification device registration. If adding a relay, proof-bind exchanged grants and specify what signing authority the relay has; if offering direct HTTP LAN mode, communicate its transport trust clearly.
