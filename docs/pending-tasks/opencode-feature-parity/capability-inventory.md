## Read this first: the global blocker

**G-0: no OpenCode v2 chat can start in LUNA today.** This is E2 source evidence, independently confirmed by the coordinator. It has **not** been observed live.

- LUNA decides that a spawned server is ready, and which wire generation it speaks, only when a 2xx JSON body containing `version` arrives from `GET /api/health` or `GET /global/health` (`crates/harness/src/opencode/mod.rs:474-490`, spawn loop `:576-597`).
- `/api/health` exists at v2.0.3 (`d44b52ca`, the version the adapter claims) and was removed in **v2.0.4** (`13453f2da8c`). It is absent in every OpenAPI spec through v2.0.24 and head.
- At v2.0.22, `/api/health` returns an empty 404. `/global/health` falls through to the embedded web UI and returns `200 text/html` (`oc2:cli/src/services/web-ui.ts:17-54`).
- So each spawn polls until the 300 s startup deadline and fails with "opencode serve did not become healthy" (`mod.rs:589-596`). Model and command discovery probes block the same way.
- The v2 readiness endpoint is `GET /api/info` (503 while booting, 200 when ready, `oc2:server/src/process.ts:185-214`).
- Whether a GUI-launched LUNA actually selects v2 depends on the login-shell probe (`crates/harness/src/shell_env.rs:126-138`). It normally does select v2; the silent fallback to v1 is described at F-WS-12.
- Two more hard breakers sit directly behind G-0: the permission reply body (`decision`, S0) and the command body (`name`, S1). See [tool-and-event-matrix.md](tool-and-event-matrix.md) §2.

**How to read the dimensions while G-0 stands.** For v2, **Data fidelity** and **Product connection** describe the LUNA code path *behind* the blocker: what users would get once OC-02 and OC-03 fix boot and the request contract. That is what determines the remaining work. The v1 (1.18.34) path is mentioned only where it differs materially.

**Verification** is `unverified` for every verifiable OpenCode row (the rest are `n/a`). No retained real-binary or E2E evidence against v2.0.22 exists for any LUNA path. The only live 2.x evidence is a harness-only probe against 2.0.3 (LUNA commit `67c960f4`, 2026-09-16, E4).

## Parity scope (PD-14, 2026-10-07)

Parity means OpenCode behaves like Codex and Claude through LUNA's **existing** shared mechanisms; see [provider-parity-contract.md](provider-parity-contract.md). Rows for OpenCode-only features keep their native assessment for the record, but their WP column reads **"— (not pursued, PD-14)"**. Rows whose target is "the same hook as Claude/Codex" say so in the route column.

The contract's §1 compares the shared hooks and events provider by provider. Subagents, side chats and child chats are in its §2–§4.
