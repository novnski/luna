# Source research and exclusion ledger

Source cuts: Zeron `40091d469aa8a3f1ab1ec7cb404957b742940278`; LUNA `c85fed541461b7aad62df2bfd495e7059e36d3f1`. Review date: 2026-10-11, Europe/Bucharest. The inventory covers the commits after the local Zeron baseline `b42fc2b8fbf247dd92796c2917f277535cea91ac`, not only the latest release bump.

## ZI-01: the snapshot index is isolated, but its objects are not

In LUNA, [`snapshot_tree`](../../../crates/engine/src/diff_sync.rs) creates a temporary `GIT_INDEX_FILE`, then executes `git add -A --ignore-errors .` and `git write-tree`. It does not redirect `GIT_OBJECT_DIRECTORY`. Git therefore writes blobs and trees into the checkout's own object database. A temporary index protects staging; it does not protect the repository's objects. [`capture_turn_diff`](../../../crates/engine/src/diff_sync.rs) takes another such snapshot when Latest turn is requested.

The snapshot subprocesses use `output()` without a whole-capture timeout or kill-on-drop. There is no snapshot-specific budget for untracked files. The source has bounds for rendered diff data, but those do not bound `git add` hashing the working tree. A failed new capture or a move outside a checkout also leaves the old `turn_trees` entry intact in `note_turn_start`.

Zeron [commit 037f4c10](https://github.com/zeronsh/zeron/commit/037f4c10d67a38175b2386e776aba54355b4e941) moves this work into an engine-owned object store, using the repository as an alternate; a live snapshot owns its store until readers release it. The [current implementation](https://github.com/zeronsh/zeron/blob/40091d469aa8a3f1ab1ec7cb404957b742940278/crates/engine/src/diff_sync/turn_snapshot.rs#L1) bounds untracked files/directories and elapsed work, and layers the later snapshot over the turn-start tree. Upstream reports a severe loose-object/repacking incident; we did not establish that such an incident happened in LUNA.

The local controlled probe used two disposable repositories with one committed file, changed one untracked file and captured it three times. The current command pattern added six checkout object files; setting `GIT_OBJECT_DIRECTORY` to private storage plus `GIT_ALTERNATE_OBJECT_DIRECTORIES` to the checkout added none. The real index hash and `git status --short` remained unchanged in both. Results are retained in `inventory.json` with an explicit non-E2E limitation.

The probe is repeatable: initialize a disposable Git repository, commit `tracked.txt`, and save its real index hash and object-file count. For each of three distinct contents of `scratch.txt`, use a fresh absolute `GIT_INDEX_FILE`, run `git add -A --ignore-errors .`, then `git write-tree`. Repeat in another repository with an empty absolute object directory per capture and the checkout's objects as an alternate. Compare added object files, real index hashes and status. Never run this experiment against a user's checkout.

**Adopt the storage/budget contract, not the whole upstream diff engine.** LUNA's watcher, checkout scope, discard serialization and durable command behavior have independent changes. Also improve the presentation of omitted paths: a budget-limited capture must say it is partial rather than appearing complete.

## ZI-02: local rows retain an acknowledgement queue with no acknowledger

LUNA's [`RegistryDoc`](../../../crates/doc/src/registry.rs) retains authoritative rows and a `Vec<PendingBatch>`. `enqueue_ops` appends batches on every write; `to_bytes` persists the entire queue and `from_bytes` restores it. Its 400-operation batch cap protects the server's per-batch limit, not total queue size. There is no local-profile folding or unsent-tail coalescing in this source cut.

[`WorkspaceHostConfig`](../../../crates/engine/src/workspace_host.rs) can have no edge, but has no immutable local-only mode. Consequently a permanently local workspace retains optimistic operations that no registry server will ever acknowledge. Repeated writes to the same few rows can grow retained state with operation count rather than current workspace size.

Zeron [commit 8646bde0](https://github.com/zeronsh/zeron/commit/8646bde07e31e280dd3f7b887b465857e19527d7) includes several independent performance changes. Its [registry implementation](https://github.com/zeronsh/zeron/blob/40091d469aa8a3f1ab1ec7cb404957b742940278/crates/doc/src/registry.rs#L1) applies writes straight to rows only for a profile that can never attach to an edge. Synced replicas coalesce eligible unsent writes while preserving in-flight batches, cascades and notification-producing state transitions. Old queued snapshots are compacted on load.

The distinction is essential: `edge == None` may describe a temporarily offline synced workspace. Folding that queue into rows, then seeding those rows later, can revive data another device deleted. LUNA's [profile selection](../../../crates/engine/src/profile.rs) must supply the mode; connectivity must not infer it. Guarded projection rollback, device-write barriers and LUNA-specific sidebar/ticket behavior also have to survive migration.

Upstream's headline approximately 700 MB to 200 MB startup reduction bundles registry, SQLite, journal, watcher, archived-chat and UI changes. **Do not promise that reduction for LUNA or port the whole commit.** The selected task is bounded registry retention. Tail-first journal recovery, watcher consolidation and deferred SQLite maintenance remain measurement candidates if the focused benchmark still finds a startup bottleneck. They are not additional pending tasks from this review. LUNA already has a separate [idle presence/graphics investigation](../../performance-idle-presence.md) and [storage diagnostics proposal](../agent-workspace-app-research/luna-opportunities.md); neither implements this registry fix.

## ZI-03: preserve and expose the provider's actual checklist

LUNA already renders `ToolCall::Todo` in the transcript. However, [`TodoItem`](../../../crates/proto/src/agent.rs) has only `text` and `done`. [`Claude TodoWrite`](../../../crates/harness/src/claude/normalize.rs) turns both pending and in-progress into `done: false`. Codex's [parent notification dispatcher](../../../crates/harness/src/codex/mod.rs) has no `turn/plan/updated` consumer; unknown parent methods fall through. The occurrence in the child-routing table is a consumed child notification, not parent plan support. Legacy Codex `todoList` items alone do not establish support for current `update_plan` events.

Zeron [commit 1f7b74a7](https://github.com/zeronsh/zeron/commit/1f7b74a7fc97b0ca1d0379e77141075d73db8adf) adds additive status, [Codex plan normalization](https://github.com/zeronsh/zeron/blob/40091d469aa8a3f1ab1ec7cb404957b742940278/crates/harness/src/codex/normalize.rs#L204), a compatible fold and a [latest-checklist projection](https://github.com/zeronsh/zeron/blob/40091d469aa8a3f1ab1ec7cb404957b742940278/crates/ui/src/todo_panel.rs#L34) above the composer. It follows the newest checklist, clears on an empty update and distinguishes active work from idle history.

This helps the recurring investigate → reproduce → fix → verify journey, especially after switching among chats. Keep a compact, collapsible read-only view. A pending item is not evidence that it is actively running. A stopped turn must not keep spinning.

**Provider-version qualification:** upstream's older OpenCode `todowrite` mapping is not a contract for LUNA's OpenCode 2 adapter. LUNA's [`tools.rs`](../../../crates/harness/src/opencode/tools.rs) explicitly lists the 2.x built-ins and says the 1.x vocabulary is gone. Verify an actual supported plan event before mapping OpenCode; otherwise show no native checklist. Codex and Claude are the initial positive provider gates. Do not invent a task list from prose or restore 1.x support to claim parity.

Existing Board tickets, helper supervision and structured-workflow proposals concern different entities. The transcript trust work in SW-05 should consume this task's evidence rather than creating a second plan projection.

## ZI-04: connect tool file badges to the shipped file route

LUNA's [tool header](../../../crates/ui/src/transcript.rs) already knows paths for typed read/write/edit/patch calls and displays a file badge. That badge has hover styling, but no file-opening activation. The [shell](../../../crates/ui/src/shell.rs) already resolves Markdown workspace-file links and opens a Files tab through `open_workspace_file_link` and `add_file_surface_for_owner`, preserving the source chat.

Zeron [commit 1074bc54](https://github.com/zeronsh/zeron/commit/1074bc540b995d6b7e5a6fa5431f1a2420df8d91) connects the same badge to its existing link handler and separates badge activation from tool expansion. Reuse LUNA's route so an edited file can be inspected without manually finding it again.

The upstream default-editor button is outside this task: it is useful only when the execution workspace is local to the viewing computer and its requirement has not been established here. The selected gap is the native file jump, including correct remote-host routing. Adding a new file reader, shell command or arbitrary path authority would make this unnecessarily large.

## ZI-05: search source text, not only names or recorded conversations

Zeron [commit 3487b507](https://github.com/zeronsh/zeron/commit/3487b507fa8920ab829339f3e3ad72a4bdb45036) adds a shared bounded workspace index, source-content search and Files/In Files palette sections. Its [performance report](https://github.com/zeronsh/zeron/blob/40091d469aa8a3f1ab1ec7cb404957b742940278/docs/performance-workspace-search.md#L1) exposes both benefits and costs: paths-only indexing, bounded cached contents, per-root watchers/eviction, partial answers during indexing, extra native dependencies and imperfect allocator recovery. Those are upstream Linux measurements, not reasons to assume a faster LUNA implementation on macOS.

LUNA's [`SearchWorkspaceFiles`](../../../crates/engine/src/workspace_files.rs) walks the approved workspace and ranks path/name matches; its result contains a path and directory flag, not matching text and a line. The [command palette](../../../crates/ui/src/shell/command_palette.rs) already searches conversations and recorded activity. That is not an on-disk source search. IC-5 is also transcript search; RM-06 plans phone file browsing/search but does not own an existing desktop content-search implementation.

The useful addition is small: search literal source text in the selected chat's approved checkout/host and open the exact matching file/line. This helps find API handlers, config keys and error strings during code and support investigations. Keep the current palette, file authority and editor. Do not replace L14, add a global machine-content index or import the entire tabbed palette.

**Adopt the capability before the dependency.** Upstream's `fff-search` adds 53 lockfile entries, native libgit2/zlib/LMDB builds and another watcher version. Benchmark a bounded worker using LUNA's existing ignore/file traversal and search primitives first. Introduce an index or dependency only if measured interaction latency requires it, with explicit memory/watcher/retention budgets and current build-cache constraints.
