# Integration with existing pending work

The core program adds **CORE-00–CORE-23** as the `core-platform` workstream.
These are new implementation tasks, not renamed versions of existing features.
Every current ticket keeps its prior identity, state, evidence and detailed
acceptance. Only necessary foundation dependencies are added. Resource
reservations keep broad core extraction from colliding with narrower changes.

ZI-01/02, conversation correctness, file navigation and already-scoped operational
verification are not placed behind completion of the entire plugin program.
Core tickets use conservative `engine`, `harness` and `ui` resource prefixes
where their changes genuinely span those areas. Agents should narrow a task's
implementation before editing and update future resource definitions if needed;
do not bypass a held reservation by using a different ticket ID.
ZI-03 also reserves `proto`, matching its existing planned change to the shared
Todo wire type; its status and functional scope are unchanged.

## Scope and future additions

The initial program certifies the desktop core, public SDK/CLI, local plugins,
default provider migration, custom native presentation/media and feature
extraction. A public marketplace, arbitrary native widget ABI, commercial
extension distribution, downloaded iOS native execution and new hosted services
are future product decisions. Add separately scoped tasks when selected, using
the same package/authority/data contracts.

CORE-00 is the first next-task candidate after this planning update. This
reorders the initial foundation work intentionally because the requested core
architecture now precedes dependent feature contracts. A paused eligible ticket
still has the queue's normal resume priority; this document does not steal an
existing claim or invalidate accepted work.
