## Architecture and T3-specific behavior

- T3 has a Node WebSocket server and web, Electron desktop, and React Native mobile clients. Its Codex driver constructs the Codex adapter and probes the runtime; the session runtime spawns and initializes `codex app-server`, then starts or resumes native Codex threads. Sources: [T3 AGENTS.md:1](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/AGENTS.md#L1), [T3 apps/server/src/provider/Drivers/CodexDriver.ts:250](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/apps/server/src/provider/Drivers/CodexDriver.ts#L250), [T3 apps/server/src/provider/Layers/CodexSessionRuntime.ts:2481](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/apps/server/src/provider/Layers/CodexSessionRuntime.ts#L2481).
- T3 translates four permission modes to Codex sandbox/approval policy at both thread and turn creation: Supervised → untrusted/read-only; Auto-accept edits → on-request/workspace-write; Auto → same sandbox with `auto_review`; Full access → never/danger-full-access. It deliberately sets `approvalsReviewer` on resume to avoid a sticky prior reviewer. [T3 apps/server/src/provider/Layers/CodexSessionRuntime.ts:515](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/apps/server/src/provider/Layers/CodexSessionRuntime.ts#L515), [T3 apps/server/src/provider/Layers/CodexSessionRuntime.ts:568](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/apps/server/src/provider/Layers/CodexSessionRuntime.ts#L568).
- T3 implements a ChatGPT managed sign-in that installs/acquires a Codex executable, injects an `ACCESS_TOKEN` with its own Responses provider configuration, and removes ambient CLI overrides. Existing CLI logins remain another mode. Managed authentication was merged on 2026-09-29 in `27bdf1aa14`. [T3 apps/server/src/provider/CodexManagedRuntime.ts:18](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/apps/server/src/provider/CodexManagedRuntime.ts#L18), [T3 apps/server/src/provider/CodexManagedRuntime.ts:90](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/apps/server/src/provider/CodexManagedRuntime.ts#L90), [T3 docs/user/providers-codex.md:1](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/docs/user/providers-codex.md#L1).
- Multiple Codex accounts can share conversation state through a `CODEX_HOME` shadow overlay while keeping `auth.json` and model cache private; compatible instances use the shared home as a continuation key. T3 also handles remote ChatGPT OAuth handoff with a single persistent refresh owner. [T3 apps/server/src/provider/Drivers/CodexHomeLayout.ts:19](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/apps/server/src/provider/Drivers/CodexHomeLayout.ts#L19), [T3 apps/server/src/provider/Drivers/CodexHomeLayout.ts:44](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/apps/server/src/provider/Drivers/CodexHomeLayout.ts#L44), [T3 apps/server/src/provider/Drivers/CodexHomeLayout.ts:373](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/apps/server/src/provider/Drivers/CodexHomeLayout.ts#L373), [T3 docs/internals/providers.md:51](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/docs/internals/providers.md#L51).

## Recent changes and implications for LUNA

- The 2026-09-29 `422248515a` commit regenerated app-server bindings against Codex 0.159, adding schema surface. The last Codex feature work with obvious user impact was managed ChatGPT sign-in (`27bdf1aa14`, 2026-09-29) and service tier catalog fix (`451afcb22d`, 2026-09-29). A binding regeneration alone is not proof that a new method reaches any client.
- The most useful T3 ideas to compare with LUNA, **without assuming LUNA lacks them**, are: durable async and blocking question panels; granular permission and MCP elicitation cards across clients; image-by-path turn input; shared-home multi-account continuation; compact/revert with clear filesystem/conversation separation; subagent status and stop-all; workspace skill discovery; accurate live context/reasoning/tool logs. Native review targets, native fork, queue editing, goals, live turn setting changes, rich typed attachments, and app/plugin management should be judged against Codex directly because T3 does not currently cover them.
- Caution: Codex installation/protocol versions matter. T3 hardwires newer request types but rejects unknown server request methods. For unsupported responses such as dynamic tools and URL elicitation, enabling a newer Codex feature without a handler can result in a rejected tool/request even though generated types mention it.
