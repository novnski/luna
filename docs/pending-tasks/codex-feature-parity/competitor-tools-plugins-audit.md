# BB and T3: Codex tool activity and installed skill selection

Part of [the pending Codex parity research](README.md). This audit records inspected behavior and proposals; implementation and new live verification remain pending. Source links are pinned to the inspected revisions.


Read-only at BB `f117245` and T3 `8792f95762` on 2026-09-30. T3's `docs/research/` was already untracked and untouched. No live provider calls or app launches. This compares competitor implementation patterns; it makes no claim about LUNA without LUNA's own audit.

## Steering semantics

- **BB** offers explicit active-turn `turn/steer` injection ([BB plugins/provider-codex/src/bridge/bridge.ts:1881](https://github.com/get-bb/bb/blob/f1172452bb0ca60c042ce884b3f8b98112fe377d/plugins/provider-codex/src/bridge/bridge.ts#L1881)) with expected-turn-ID protection ([BB packages/agent-runtime/src/runtime.ts:2088](https://github.com/get-bb/bb/blob/f1172452bb0ca60c042ce884b3f8b98112fe377d/packages/agent-runtime/src/runtime.ts#L2088)). Send modes steer active, start idle, or store a distinct BB queue entry waiting for `thread-busy`/`stopping`; pending user interaction blocks a new user prompt. [BB apps/server/src/services/threads/thread-send.ts:168](https://github.com/get-bb/bb/blob/f1172452bb0ca60c042ce884b3f8b98112fe377d/apps/server/src/services/threads/thread-send.ts#L168), `:214`; [BB apps/server/src/services/threads/queued-messages.ts:230](https://github.com/get-bb/bb/blob/f1172452bb0ca60c042ce884b3f8b98112fe377d/apps/server/src/services/threads/queued-messages.ts#L230). Native Codex editable queue is not used. This gives the user an explicit choice between steering this turn and running next, without interrupting a tool automatically.
- **T3** does not call Codex `turn/steer` in its Codex adapter. It sends `turn/start` even while another turn runs; Codex returns a queued turn ID, which T3 carefully does not mistake for the active ID. [T3 apps/server/src/provider/Layers/CodexSessionRuntime.ts:2567](https://github.com/pingdotgg/t3code/blob/8792f95762092ea33e74d41a07e8818befd84970/apps/server/src/provider/Layers/CodexSessionRuntime.ts#L2567), `:2596`. Stop settles pending approvals and user input before interrupting children and the active parent turn, avoiding deadlock; it bounds child interruption. Same file `:2614`. T3's queued-follow-up behavior therefore differs from BB's active-turn steer; tool-boundary timing of native queued work should be verified in Codex itself.

## LUNA comparison prompts

- For each Codex activity type, trace native item/notification -> engine event -> persisted history -> UI row -> expanded output. Treat Read/Search/explore shell commands as command activity unless a deliberate classifier presents them more specifically. Preserve actual command, cwd, exit code, raw output, file paths, patch/diff and duration in the stored record even when the collapsed row is brief.
- Render tool output at a bounded size with an explicit omitted count and lazy full-output retrieval; retain safe fallback when output expires. BB is a good reference. Preserve media content types from MCP/dynamic tool results instead of flattening image content to text.
- Separate native Codex app inventory selection from installation/management. T3's source-badged skill picker and per-account/per-project snapshot model are useful, but neither competitor demonstrates full native `@app` selection. BB's generic plugin mentions are its own extension API.
