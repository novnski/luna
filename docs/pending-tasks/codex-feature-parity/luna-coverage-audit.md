## Ranked gaps by likely user value

1. **P1 — Native image input is omitted from every Codex turn.** Luna stages image attachments and records absolute local paths in `RunRequest.attachments` ([LUNA crates/proto/src/agent.rs:325-334](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/proto/src/agent.rs#L325)), while the composer adds a human-readable path trailer ([LUNA crates/ui/src/attachments.rs:50-66](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/ui/src/attachments.rs#L50)) and engine resolves paths ([LUNA crates/engine/src/doc_host.rs:6768-6783](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/engine/src/doc_host.rs#L6768)). The Codex adapter serializes only `{type:"text"}` for first-turn input and live steers ([LUNA crates/harness/src/codex/mod.rs:1307-1311,1858-1863](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/harness/src/codex/mod.rs#L1307)). The provider might later open a path via a tool, but the model does not receive the actual image as native image content at input time. This is a clear parity loss for screenshots and design/image questions; T3/BB have native local image support. Recommendation: use Codex's typed `localImage` turn input for staged images (including steer/follow-up), preserving the text trailer for Luna history if desired; verify an image-only prompt from composer to provider and back.

2. **P1/P2 — Generic MCP elicitation is declined.** The adapter accepts `mcpServer/elicitation/request` only when `serverName == "computer-use"`, the active thread/turn matches, a `once` form choice exists, and it can identify an app; every other MCP form or URL request receives `{action:"decline"}` ([LUNA crates/harness/src/codex/mod.rs:2317-2336](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/harness/src/codex/mod.rs#L2317), `:2532-2595`). Codex's normal MCP tools otherwise run and produce transcript chips ([LUNA crates/harness/src/codex/normalize.rs:1134-1165](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/harness/src/codex/normalize.rs#L1134)). Servers that need follow-up data or an authorization URL cannot complete that flow in Luna. Recommendation: add a generic typed elicitation UI/response bridge for allowed form and URL requests, with exact server/turn binding and bounded content.

The only Luna Codex app-server RPC inventory has no review method ([LUNA crates/harness/src/codex/native.rs:23-34](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/harness/src/codex/native.rs#L23)), and its run adapter starts only an ordinary `turn/start` ([LUNA crates/harness/src/codex/mod.rs:1039-1044,1307-1356](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/harness/src/codex/mod.rs#L1039)). A generic bounded unknown-item fallback or explicit mapping plus fixture capture against the installed CLI would make future version drift visible. `mcpToolCall` result projection copies only text content ([LUNA crates/harness/src/codex/normalize.rs:1146-1165](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/harness/src/codex/normalize.rs#L1146)), so image/resource MCP result content is not shown in Luna even when the provider consumes it.
- **Quick display win: Mermaid diagrams render in file previews but not Codex chat.** The markdown renderer requires a diagram media adapter ([LUNA crates/ui/src/markdown/render.rs:1845-1846](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/ui/src/markdown/render.rs#L1845)); Files preview supplies one ([LUNA crates/ui/src/files/markdown_preview.rs:625-639](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/ui/src/files/markdown_preview.rs#L625)), while transcript render paths explicitly pass `media: None` ([LUNA crates/ui/src/transcript.rs:6136,6186](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/ui/src/transcript.rs#L6136)). The existing scope was documented as excluding chat ([LUNA docs/markdown-preview.md:13](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/docs/markdown-preview.md#L13)). Recent Codex CLI TUI renders Mermaid, so wiring the existing adapter into chat would improve visible output parity with limited protocol work. This is a presentation gap, not a Codex harness execution gap.
- **Experimental controls are not yet worth treating as core parity gaps.** Current Codex advertises native editable thread queue, live `turn/settings/update` (model/effort/tier/reviewer), memory mode/status, background terminals, realtime voice/remote control. Luna already has its own durable queued messages ([LUNA crates/engine/src/rpc.rs:3161-3320](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/engine/src/rpc.rs#L3161)), next-turn model/effort/tier changes (`:4501-4560`), local terminals, and inherited provider memory defaults; the native semantics/telemetry remain different. Prioritize these only after a concrete user flow or stability need is identified. In particular, Luna's `supports_live_mode_change: false` is explicit for Codex ([LUNA crates/engine/src/permissions.rs:17-31](https://github.com/novnski/luna/blob/e71d90caad0798ca6dcec28da4b352d8f8c39c0c/crates/engine/src/permissions.rs#L17)), so switching permission modes during a running turn waits for a new safe boundary, despite the newer experimental update API.

## Recommended sequence

Ship native image input first (including image-only prompts and steer), then generic MCP elicitation and native Review. Add goal status and controls with careful interaction tests against Luna queue/recovery. Next add the experimental structured Plan mode and visible dynamic-tool activity. Fold richer approval context and native history revert into the next parity pass. Maintain a source/schema coverage matrix when bumping the validated Codex CLI beyond 0.154.0, because unknown item/notification cases currently disappear with no user-facing trace.
