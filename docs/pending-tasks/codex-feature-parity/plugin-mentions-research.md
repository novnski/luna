## Answer: bundle plugins and connected apps are distinct

Codex app-server exposes three different inventories: `skills/list` for skill files, `plugin/list`/`plugin/installed` for **bundles** of skills/MCP servers/apps, and `app/list`/`app/installed`/`app/read` for **connector apps**. `plugin/installed` takes optional absolute `cwds` and no install suggestions by default; it combines installed local and cached remote entries. `plugin/list` can also return uninstalled marketplace catalog rows and is what Codex TUI currently uses for its plugin-mention picker, filtering to `installed && enabled && availability != DisabledByAdmin`. `app/installed` reports per-thread effective `enabled` and `callable`; `app/read` supplies display name, description and icon without loading tool details. ## Native invocation: exact path is the key

`turn/start.input` accepts `UserInput::Mention { name, path }` in addition to text, images, audio and skills; `Text.textElements` contains UI byte ranges, **not** the app/plugin identity. For an installed plugin choose `path: "plugin://" + PluginSummary.id`; for a connector choose `path: "app://" + InstalledApp.id`. The TUI emits these structured paths after validating against its loaded candidate list. Plugin text links such as `[@Figma](plugin://id)` are also recognized; app linked text uses the `$` sigil (`[$Figma](app://id)`), so structured mention items are the robust way to support a single LUNA `@` selector for both. ## Smallest LUNA design that preserves native semantics

1. Add a **read-only, host-routed Codex mention catalog** on the owning device, using the selected execution account/CODEX_HOME and effective cwd or worktree. Request `plugin/installed {cwds:[cwd]}` with no suggestions; keep only `installed && enabled && availability != DISABLED_BY_ADMIN`. Request `app/installed {threadId?}` and retain `callable` apps, then batch `app/read {appIds,threadId?,includeTools:false}` for display metadata. If the installed method is absent on an older CLI, fall back to `plugin/list` filtered to installed and `app/list` filtered to accessible/enabled; report method errors rather than treating them as an empty catalog. Distinguish rows as `plugin` or `app` even when names collide. This is an installed-use picker; `plugin/read` is optional on detail demand. Codex's own TUI already demonstrates the app fallback and bounded app metadata enrichment. [Codex codex-rs/tui/src/app/connector_mentions.rs:56](https://github.com/openai/codex/blob/ceea67163f93b4317c9352d1cd2af9fee32537b9/codex-rs/tui/src/app/connector_mentions.rs#L56), [Codex codex-rs/tui/src/app/plugin_mentions.rs:38](https://github.com/openai/codex/blob/ceea67163f93b4317c9352d1cd2af9fee32537b9/codex-rs/tui/src/app/plugin_mentions.rs#L38).
2. Return only `kind`, stable native `id`, `displayName`, short description, icon URL or host-local icon reference, and availability from the host. Cache by `(hostDeviceId, selectedProviderAccountId/effectiveCODEX_HOME, canonicalCwd, nativeCodexVersion)`; include `threadId` for the callable-app slice because app gating can depend on the loaded thread. Keep a short freshness window (suggest five minutes), refresh when the picker opens after expiry, and allow a manual retry. Invalidate on selected account/home/project/worktree change, Codex update or reconnect, explicit refresh, and app-list/thread-settings/account notifications where available. Codex provides no general `plugin/list/updated` notification, so rely on bounded TTL plus explicit refresh for external installs. Preserve last successful rows with a visible stale label during a transient offline failure; never relabel stale as fresh or convert failure to “No plugins.” No token, auth file, or plugin package data belongs in this cache. Native Codex itself clears internal plugin/skill caches after effective plugin changes. [Codex codex-rs/app-server/src/effective_plugin_change.rs:23](https://github.com/openai/codex/blob/ceea67163f93b4317c9352d1cd2af9fee32537b9/codex-rs/app-server/src/effective_plugin_change.rs#L23), [Codex codex-rs/app-server-protocol/src/protocol/v2/apps.rs:31](https://github.com/openai/codex/blob/ceea67163f93b4317c9352d1cd2af9fee32537b9/codex-rs/app-server-protocol/src/protocol/v2/apps.rs#L31), [Codex codex-rs/app-server-protocol/src/protocol/v2/plugin.rs:128](https://github.com/openai/codex/blob/ceea67163f93b4317c9352d1cd2af9fee32537b9/codex-rs/app-server-protocol/src/protocol/v2/plugin.rs#L128).
3. Extend LUNA's existing `@` popup with file/plugin/app sections. On selection, keep the exact native ID, not only its label, in an edit-safe chip and the draft/queued message payload. At host dispatch, form `turn/start.input` as text plus deduplicated `Mention {name:displayName,path:"plugin://<id>"|"app://<id>"}` items, preserving the ordinary user text and existing file mentions. Do the same for `turn/steer`; queued delivery must keep IDs until the host sends. A backward-compatible optional mention vector in the run/queue/draft contracts is safer than deriving identity from a display label or accepting arbitrary pasted syntax as a selected catalog row. If the host can no longer resolve a selected ID under the execution account, keep the draft and surface a clear unavailable message. LUNA already has edit-generation guards and typed file-result popover behavior worth reusing.
