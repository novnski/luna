## BB-specific lessons for LUNA to inspect

1. **Separate protocol parity from product affordance.** BB's Codex bridge supports native checkpoint forks, stream deltas and permissions while many newer notifications remain raw. Inspect LUNA's request decoder and event normalizer, not generated types or UI labels. BB explicitly inventories notification coverage ([BB plugins/provider-codex/src/visibility.ts:125](https://github.com/get-bb/bb/blob/f1172452bb0ca60c042ce884b3f8b98112fe377d/plugins/provider-codex/src/visibility.ts#L125)).
2. **Useful differentiated integration:** BB injects project and plugin instructions/dynamic tools into Codex and maps live tool calls back to BB ([BB apps/server/src/services/threads/thread-runtime-config.ts:220](https://github.com/get-bb/bb/blob/f1172452bb0ca60c042ce884b3f8b98112fe377d/apps/server/src/services/threads/thread-runtime-config.ts#L220); [BB plugins/provider-codex/src/bridge/bridge.ts:804](https://github.com/get-bb/bb/blob/f1172452bb0ca60c042ce884b3f8b98112fe377d/plugins/provider-codex/src/bridge/bridge.ts#L804)). It indexes native Codex skill roots including enabled Codex plugin cache skills (`native-roots.ts:53`, `:248`) while leaving the underlying Codex engine to load its own config.
3. **High-use parity targets if LUNA lacks them:** native structured questions with multiple options/free text (BB's replacement is off by default), explicit turn/session network and file permission grants, native review action, typed image prompt inputs, accurate plan steps and native plan-mode controls, and exposing MCP/app auth health rather than raw event logs. BB is strongest on per-turn settings, BB queue, skill discoverability, subagent timeline, and fail-safe resume; it is not a complete reference for newer Codex native features.
