# E2E acceptance and switching gates

These are proposed acceptance criteria, **not test results**. Read the [task ledger](README.md#priorities-dependencies-and-task-ledger) and [implementation](implementation.md) first. Each contract gets one primary owner; consume existing proof rather than mirror it across engine, harness and UI.

## Authoring and evidence rules

Before implementation/new tests, record the behavior, credible failure, existing coverage gap and strongest boundary. Extend an existing owner when it can reach the failure. A different layer needs a distinct transport/native-lifecycle risk. No post-implementation unit tests, test-only production accessors, source-string assertions, generic fake shared across providers, or expected values generated by the renderer/helper under test.

Scripted peers drive real adapter/engine/journal/document paths and preserve each provider's native frame shape. They protect deterministic protocol/lifecycle contracts; they do not certify a real account, effective MCP attachment or native pixels. Live Codex and Claude evidence is independently required for the selected switching modes. OpenCode remains required wherever the external IC plan requires it.

Every refusal scenario first demonstrates a healthy allowed operation, then verifies the intended denial reason and zero forbidden downstream effects. An expired credential, nonexistent target or broken connection must not accidentally pass an authority test. Poll for authoritative events/receipts rather than use sleeps as a completion assertion.

## Failure contracts and primary ownership

| Risk | Existing strongest owner to inspect first | Missing evidence to add only if needed |
| --- | --- | --- |
| Configured server falsely shown callable; mode/identity drift | `claude_mcp_inventory`, provider MCP suites, integration picker | Real active-session calls and native UI readback after relevant generation changes |
| Restricted-mode permission/config escape | Engine `claude_permissions`, harness permission/MCP startup suites | Selected external tool call through actual CLI with required approval and denied upstream counter |
| Skill scope/revision mismatch | Existing managed-skill lifecycle/extension input tests | The chosen real mode actually receives and uses the approved skill |
| Duplicate/unknown external side effect | Bridge approval/call fences, `cross_task_tools`, recovery | Disposable service counter across a transport-loss/restart boundary |
| Text/tool/child ordering or duplicate parts | `timeline_order_e2e`, provider result and subagent owners | Uncovered late-child native frame or actual viewport lifecycle; preserve covered cases |
| Queued/steered input or attachment loses owner | `message_queue`, `native_inputs`, `queued_attachments` | Actual native input/receipt and question/UI interleaving |
| Restart/handoff/search changes context or grants | `restart_resume`, history/local import, workspace controls | Real provider resume plus native history navigation and deliberate new-chat handoff |
| Media dropped or another task's bytes exposed | Native result envelopes, host upload/asset authorization | Actual supported image delivery, lazy native display and privacy/owner readback |
| Browser action follows focus to wrong target | Existing computer-use tool boundary and target identity | Real two-target DOM/AX/pixel counter evidence |
| HTML/app/Find correctness | IC H01–H10, A01–A07, S01–S06/P01 | Consume its canonical evidence; only add the distinct whole-workflow outcome |
| Helper stop accepts receipt but task continues | Existing cross-task control/approval/session ownership | Exact target/run terminal readback with sibling still running |
| Board/automation UI resurrects stale state | Existing fix package/suites/production UI fixtures | Current native replay; late-transport order only if the existing proof lacks that risk |
| Scheduled task repeats or misses delivery silently | `automations_e2e`, native automation runner | Actual two-run destination and host sleep/restart campaign |

Proposed additions are scenario/runner contracts, not claims that a named new executable exists. SW-00 pins exact owners and invocations before authors add code.

## Acceptance scenarios

### E01 — active-session inventory (SW-00/SW-01)

Create fresh and resumed Codex/Claude chats in each selected mode using an existing configured fixture server. Compare Settings/picker facts with an actual read returning an independently chosen nonce. Change mode/configuration at the safe boundary and verify generation, unavailable reason, preserved draft and actual callability. Native app/skill identity must come from selection, not a pasted link. A control-only inspection or Connected row cannot satisfy the active-call assertion. **Evidence:** capability matrix, launch/schema facts, server counter, call/result receipts and UI captures.

### E02 — scoped external MCP permissions (SW-02)

In Claude Ask, execute a permitted fixture read, decline a write, then allow one exact staged write; expect read data, zero declined mutations and one approved mutation. Repeat on eligible Auto and the selected Codex mode with their actual reviewer/grant semantics. Confirm user/project permission overrides and a harmless hook sentinel were not loaded/executed in the restricted run. Wrong parent/machine/session scope and a stale call must be refused for the intended guard. No hidden Full/admin process may service a call. **Primary owner:** permission/bridge boundary; live CLI capture adds native enforcement evidence. Ineligible Auto is blocked for that variant, never recorded as passed.

### E03 — approved skill behavior and migration (SW-03/SW-11)

Use two fixture projects with distinct skill content/scope and one deliberately stale revision. Reuse current copy/install APIs, select the intended skill, perform its observable bounded workflow through allowed tools, then resume and repeat. Compare delivered native identity or attributed guidance hash against an independently prepared fixture; include the real tool/output receipts rather than merely asserting prompt text. The second project's override and unrelated settings survive; an unavailable native-only command remains labelled unavailable; no hook/permission grant is inferred from guidance. **Primary owner:** current managed-skill/extension contracts, with one actual-mode workflow capture.

### E04 — real support/infrastructure evidence to draft (SW-04)

Use one approved read-only support target and one infrastructure/source target. Through existing Executor connections and exact discovered tool paths, gather the required Intercom/Slack and account/usage/monitor facts, verify representative real response fields, inspect current owning source, and produce a draft/handoff with links and query times. Repeat on Codex and Claude, resume after restart, and compare with independent readbacks. A failed/auth-unavailable read stays explicit and cannot produce a confident fabricated result. No customer reply is sent. **Evidence:** sanitized request/response facts, live timestamps, source revision, final draft, tool IDs and restart readback.

### E05 — staged write, uncertainty and no resend (SW-02/SW-04)

Drive the production bridge against a disposable independently logged service. Review/decline one action, approve another, then break transport after service commit but before acknowledgement and restart. Assert zero effects for decline, one committed approved effect, an unknown/reconciliation state where appropriate, and no second request silently issued. A later read recovers evidence without replaying the mutation. Also cover failure before submission using the existing retry contract. **Primary owner:** bridge/queue/recovery E2E. The service log is the oracle; the agent's success wording is not.

### E06 — chronological truth and native viewport (SW-05/SW-06)

Run text → tool → text, distinct back-to-back messages, an intervening notice, and child/late results with independent native IDs. Compare native frames, journal sequence, persisted parts and visible row ownership. While viewing a mid-history anchor, stream/update/prepend/resize/split and restart; the visible anchor and content remain consistent. Reuse existing deterministic cases. A new regression must fail on baseline for the specified reason. **Primary owners:** `timeline_order_e2e` for fold/identity; native transcript QA for viewport risk. IC H09 owns interactive-card view lifecycle once present.

### E07 — late questions, queued images and steering (SW-06)

Ask a nonblocking question, continue work, revise the question and deliver the later answer through its actual ID/revision. Queue an image-bearing follow-up, then exercise live steer and a turn-completion race. Verify one accepted delivery, correct target input/image and preserved composer selection/draft; stale question answers cannot approve another action. Stop/restart during a queued-but-unaccepted command and observe the existing receipt policy. **Primary owners:** queue/native-input/attachment boundaries. **Native evidence:** actual outgoing provider input, question state, receipt and transcript, not a fixed sleep or echoed model promise.

### E08 — restart, history boundaries and handoff (SW-06)

Resume a real provider conversation, fork at an explicit checkpoint, rewind the selected task, and prepare a deliberate portable handoff. Verify source checkpoint, task lineage, model/account/mode, branch and preserved non-rewound files where the existing contract requires them. A fork does not inherit source approvals or another view's live tool bridge; unknown delivery remains unknown until reconciled. Claude unsupported out-of-turn compact gets its precise existing state. **Primary owner:** existing restart/history/workspace contracts; native QA proves actual resume/focus behavior.

### E09 — visual tool output and privacy (SW-09)

Return real supported image plus text/resource content through each selected provider/gateway and display the image in the owning chat/detail view. Reopen after restart through authorized host bytes; compare image digest/dimensions to the independent fixture. Try another task's reference, prose-only path, removed source and unavailable host: get the intended refusal/availability state without leaking bytes. Check that synced text/metadata contains no screenshot base64 or credential-bearing URLs. Keep intentional computer-use journal omission, with an explicit retained-asset path when needed. **Primary owner:** actual result → authorized asset → UI retrieval boundary; unavailable bytes cannot pass the positive image case.

### E10 — exact browser/native target (SW-08)

Open independent targets A and B with observable DOM/AX counters. Bind the tool session to A, focus B, then read/click/capture A; A changes once and B remains unchanged. Close A or revoke access and verify a precise failure without retargeting. Return actual pixels/accessibility facts into LUNA and use them in one amendment. Record which browser is controlled; embedded WKWebView support cannot be inferred from a separate Chromium target. **Evidence:** target IDs, counters, actual tool outputs, before/after PNGs and LUNA result readback.

### E11 — inspect, revise and reopen a visual (SW-07/SW-08)

Consume IC's canonical renderer/storage/provider evidence. Ask for a self-contained mock/chart, preview and inspect its pixels/diagnostics, publish, click a real control, amend the source and publish the second immutable result. Restart and reopen/export both references; verify original and revised content identities and interaction outcome. Keep ordinary browser authority separate from isolated HTML. Repeat through real Codex and Claude; IC retains its all-provider requirements. **Unique added contract:** complete agent-to-user visual iteration. H01–H09/H06 remain the owners of rendering, retries, isolation and view lifecycle.

### E12 — three helpers and exact stop (SW-10)

On an explicit request create three persistent helpers with distinct briefs, provider/execution choices and one selected isolated checkout. Let two report out of order; stop the exact still-running helper through the authorized path, then verify terminal state/remaining descendants and a sibling still running. Simultaneously switch views and edit the parent draft; those states remain intact. An unrelated task or child-origin request without the proper grant is refused. Distinguish accepted stop, completion-race no-op, offline/unknown and confirmed stop. **Primary owner:** cross-task authority/backend control; native QA proves readable Activity/status placement.

### E13 — coordinated code delivery (SW-10)

Use a disposable real Git project and local bare remote, implementation/review helpers and the user's approved delivery skill. Implement a bounded feature, run its independent E2E, inspect the actual diff, commit/push through existing paths, and verify both refs and preserved unrelated fixture work. Add draft-PR verification only with an explicitly selected fixture/staging forge; local Git proof is not an authenticated GitHub certification. Prepare a fresh-chat handoff with exact SHA, branch, findings and next action. **Unique contract:** delivery workflow joins existing helpers/Git/checks; do not duplicate primitive Git or Board review tests.

### E14 — past work and general-work scope (SW-11)

Import sanitized representative Codex/Claude history using existing local import into a normal project. Find the old task through global search, verify provider/source/archive attribution and exact branch/context, then navigate an off-screen passage through IC S01–S06. Seed a fresh task without resuming a merged branch or minting grants from history. Use a general folder-backed workspace without requiring a Git repository; project/host scope remains explicit. **Primary owners:** existing import/history search plus IC's Find contracts. Missing older history is shown as unavailable rather than filled in.

### E15 — shipped Board/automation replay (SW-12)

Reuse the five-ticket fix package. In a disposable native project, delete a settled ticket, retain its reserved identity/history, and verify banners/counts and hidden-page reentry. Active/queued/uncertain work refuses deletion. Reuse an actual structured own-chat image to create/update a ticket and send it to the selected main/side worker; foreign/prose-only references refuse correctly. Delete/update an automation and reopen immediately: the committed new state wins and stale results cannot resurrect it. Verify editor at light/dark/narrow sizes. **Primary owners:** existing Board/automation suites and production UI fixtures; add adversarial native transport ordering only if current coverage lacks it. Passing baseline means no new feature/ticket.

### E16 — actual recurrence and host lifecycle (SW-13)

Observe two real scheduled runs in an existing chat and a fresh-chat destination, with intended model/mode/tools and notification behavior. Capture occurrence IDs, input delivery and final results. Pause/delete/update, sleep/restart the host across a due slot, and verify documented missed-slot/lease/unknown handling and absence of duplicate fixture effects. Distinguish already admitted work from a new forbidden occurrence. **Primary owner:** `automations_e2e` for durable/dedup contracts; the existing native runner for scheduler → provider → UI/host lifecycle. Configuration/cron parsing alone cannot pass.

### E17 — additional interactive app (SW-14)

Consume IC A01–A07 on one actual required app: original-session capture, real data read, one confirmed fixture mutation, declined mutation with no effect, stale/rebound-session refusal and persisted readable snapshot. Capture resource digest/handshake/receipts. Claude/OpenCode fallback may pass its honesty contract, but cannot certify an unavailable app operation. No duplicate provider/MCP registration or admin-process execution. **Owner:** IC-4/IC-6; this plan adds only the chosen user journey and its required/optional decision.

### E18 — conditional requirement decision (SW-16)

Record the actual voice/phone/offline scenario, why it matters, whether it gates switching and its canonical owner. Phone control consumes the existing M0–M4 validation; voice/offline work needs its own approved failure/implementation contract. The output is a decision record, not a claim of a delivered feature. If selected as required, attach that owner's real device/provider evidence and add its gate to SW-15.

### E19 — core switching campaign (SW-15)

Require independent pass artifacts for support/source investigation, long-session recovery, visual iteration/computer use, supervised code delivery, skill/history migration, the shipped Board replay and local recurrence. Run with the same intended accounts/modes twice, with an engine/app restart between attempts. Native pixels, real tool/source data and actual receipts must support the relevant claims. Record every exit to another agent interface, blocked capability and scope limit. A required failed/blocked journey prevents a complete-switch result; optional features stay listed. Reuse E01–E18 evidence rather than add a blanket duplicate suite.

## Verifiable artifact contract

Each attempt retains a scoped directory such as `target/qa/luna-only-workflows/<run-id>/`; preserve/hash reviewed evidence before cleaning any disposable app/fixture. A manifest records:

- Scenario/task ID, baseline/current SHA, provider/CLI/schema/account identifier, mode and effective ceilings, source/connection owner, platform and four QA identity values.
- Exact command/arguments, start/end, exit code, attempts and **pass/fail/blocked/not-run** status. A skipped or unsupported capability is not a pass of its positive case.
- Sanitized native frames, journal/document excerpts, actual call/command/approval/occurrence IDs, independent downstream/readback data and expected invariants.
- UI screenshots/AX/focus/viewport facts where required, artifact hashes/export bytes or Git refs, and bounded timing/resource facts when they are part of the contract.
- Fixture/replay inputs, a concise replay procedure, limitations, explicit live-versus-scripted proof and `SHA256SUMS`.

Keep private customer response bytes, authentication material, cookies, recordings and screenshot contents in access-controlled local evidence only when necessary. Committed summaries contain redacted facts/hashes, never `.env` or tokens. Do not broaden journal/sync retention to make tests convenient. Failure artifacts remain available and cite the intended failing contract; reruns record the repair and only affected checks.

After review, mark the owning task with its result/evidence, preserve unrelated work/data/cache, remove only disposable owned resources, hand back the verified primary app, and deliver through commit-and-push. A passed build, catalog entry, queued request or generated path remains an intermediate result.
